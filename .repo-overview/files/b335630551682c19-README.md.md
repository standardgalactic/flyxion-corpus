**Flyxion TeX Corpus (README.md)**

This repository aggregates all distributed TeX files attributed to *Flyxion* from various GitHub repositories, preserving their original provenance. Its purpose is to create a single, searchable corpus of essays, papers, books, and technical documents that retains metadata linking each file back to its source repository.

**Principal Ideas / Behavior**

- **Inventory & Collection**: Uses an inventory script (`flyxion-inventory.sh`) to discover TeX files containing `\documentclass` across repositories linked to `standardgalactic`. Collects 965 out of 967 candidate files, preserving drafts and alternate versions.
- **Provenance Preservation**: Retains original repository names, paths, and ownership information in the `sources/` directory structure (`sources/OWNER/REPOSITORY/original/path/document.tex`).
- **Compilation Pipeline**: Provides a repeatable LuaLaTeX compilation pipeline via `compile-flyxion-corpus.sh`, generating PDFs and extracting readable text.
- **Analysis Tools**: Includes scripts for summarizing builds, detecting duplicate texts, and reporting compilation errors (`analyze-flyxion-build.sh`).

**Important Dependencies / Outputs**

- Requires Unix-like environment with Bash and common GNU utilities plus external commands: `gh`, `jq`, `perl`, `ripgrep`, `sha256sum`, `flock`, `timeout`, `lualatex`, `pdfinfo`, `pdftotext`.
- Generates outputs under the `build/` directory, including compiled PDFs (`build/pdfs/...`), extracted text files (`build/text/...`), logs (`build/logs/...`), and manifest files for compilation results and duplicate detection.

**Completeness Assessment**

The repository appears complete in its current state as it documents all discovered TeX files and provides a full build, extraction, and analysis pipeline. However, some compiled documents may fail due to missing dependencies (e.g., external packages or fonts) that are not collected alongside the primary `.tex` files.

**Overall Status**

- **Generated**: Yes – the corpus is assembled from existing GitHub contributions.
- **Duplicated / Problematic**: No major duplication issues; however, compilation failures often indicate missing dependencies rather than incomplete works. The logs help diagnose and resolve these issues.

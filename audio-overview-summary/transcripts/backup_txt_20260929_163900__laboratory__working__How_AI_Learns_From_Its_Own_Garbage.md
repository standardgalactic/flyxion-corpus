### 1. Semantic Labeling Experiment

To test whether the definition of a fork (branch) can be divorced from token probability distributions by using semantic algorithmic strategies to cluster divergences before measuring SSD performance.

**Procedure:**
- **Step 1:** Identify specific points in code where forks occur, such as line 15 where either merge sort or quick sort could initiate.
- **Step 2:** Use a human expert or advanced semantic analyzer to verify that both algorithms (merge sort and quick sort) lead to fully functioning programs based on software engineering principles.
- **Step 3:** Trace the probability mass in the neural network back to this exact divergence point.
- **Step 4:** Run SSD training and measure if the model preserves the specific semantic branching structure.

**Evaluation Criteria:**
- Ground truth established through verified functional outcomes of both algorithms.
- Success measured by SSD’s ability to maintain the correct branching path without relying solely on probability metrics.

### 2. Corrupted Data Test (Flyxion’s Theory)

**Objective:**  
To determine if corrupted data improves performance due to structured prefixes rather than holistic properties of sequences.

**Procedure:**
- **Step 1:** Decompose the garbage dataset into three subsets:
  - **Model One:** Trained only on coherent problem restatement prefixes.
  - **Model Two:** Trained only on corrupted babbling suffixes.
  - **Model Three:** Trained on fully shuffled randomized token sequences with identical vocabulary distribution but zero syntactic structure.
- **Step 2:** Train each model using the respective dataset and run them through a live code bench test.

**Hypothesis:**
- If Model One (prefix-only) achieves a similar performance boost as observed in stress tests, while Models Two and Three show no improvement, Flyxion’s theory is validated.
- This would indicate that local regularities drive improvements rather than holistic properties of the entire sequence.

### 3. Cross-Scale Bridge Ablation

**Objective:**  
To test whether truncated prefix models (like Model C) can achieve performance comparable to perfect student models (Model A), challenging traditional views on learning versus reshaping geometry.

**Procedure:**
- **Step 1:** Train four identical base models (Student Models) on distinct data sets:
  - **Model A:** Self-generated solutions verified as 100% correct.
  - **Model B:** Full-length syntactically valid Python code but mathematically wrong.
  - **Model C:** Trained only on locally coherent prefixes, never seeing a full logical thought.
  - **Model D:** Trained on fully correct sequences from unrelated problems (e.g., web server code for sorting arrays).
- **Step 2:** Match token count and optimization steps across all models to ensure fairness.
- **Step 3:** Evaluate performance using the live code bench test.

**Evaluation Criteria:**
- If Model C performs almost as well as Model A, it would support Flyxion’s claim that local structural information is sufficient for capability gain.
- This would decouple learning from correctness and challenge traditional AI training pipeline assumptions.

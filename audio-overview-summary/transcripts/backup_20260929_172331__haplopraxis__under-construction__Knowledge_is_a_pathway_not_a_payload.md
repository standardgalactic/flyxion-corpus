### Core Concepts

1. **Preservation (P)**: This dimension ensures that physical resources are allocated for storing data, replicating it across multiple geographical nodes. The goal is to guarantee the survival of data even in catastrophic scenarios like server failures.

2. **Availability (V)**: Availability guarantees that authorized users can access the file at any time without interruption. It’s about ensuring the network remains operational and responsive to queries.

3. **Discoverability (D)**: This dimension addresses how easily an object appears in search results or populates semantic neighborhoods with related files. Discoverability is crucial for making data usable by linking it meaningfully within a larger context.

4. **Transformability (T)**: Transformability allows the file to be altered—such as running optical character recognition, summarizing content with AI models, or formatting it for physical printing. This flexibility makes the data adaptable to various uses and technologies over time.

5. **Commercial Eligibility (C)**: Commercial eligibility determines whether the object can be used to generate revenue. It’s about balancing accessibility with economic viability.

6. **Governance (G)**: Governance defines who holds the cryptographic authority to change permissions on an object, ensuring that policies like commercial rights or transformability can evolve over time without compromising security or data integrity.

### Orthogonal Dimensions

The seven dimensions are described as orthogonal, meaning they can be mixed and matched independently rather than following a sequential pipeline. This flexibility allows for highly nuanced configurations of legal and technical states tailored to specific use cases.

### Example Scenario: Hospital Data Set

Imagine a hospital uploading a massive dataset of medical imagery to URFN:

- **Preservation & Availability**: The data is preserved and available only to authorized researchers, ensuring compliance with regulations.
  
- **Discoverability**: The dataset can be set to non-discoverable, preventing it from appearing in public queries while still being accessible within the hospital’s secure environment.

- **Transformability & Commercial Eligibility**: Transformability might be enabled for statistical AI models looking for anomaly patterns, but commercial eligibility could remain strictly disabled. This separation allows researchers to innovate without risking unauthorized commercial exploitation of sensitive medical data.

### Governance and Policy Changes

Governance addresses how policies can evolve over time:

- If the hospital later decides to grant commercial rights, governance mechanisms allow a third-party ethics board or legal authority to adjust permissions accordingly.
  
- It also ensures that even if ownership or usage rights change (e.g., from non-commercial to commercial), the underlying data integrity and security remain intact.

### Data Identity Layers

URFN introduces three distinct identity layers for each object:

1. **IPayload**: The raw bytes of the file, ensuring storage efficiency by sharing identical byte sequences across multiple users.
  
2. **IHistory**: Contains provenance, ownership signatures, permissions, and economic relationships, preserving historical context and legal status.

3. **iSemantic**: Represents the object’s location in the network’s relational embedding space, allowing for dynamic re-indexing without altering the underlying identity or history.
